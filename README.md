# Zhess X – เว็บเซิร์ฟเวอร์ฉบับเต็ม

เกมกระดานผลัดตา เล่นได้ทั้งในเบราว์เซอร์และแอป APK ชุดนี้มีครบ: เกม, เซิร์ฟเวอร์ออนไลน์, กล่องจดหมาย/เช็กเวอร์ชัน, What's New อัตโนมัติ และด่านตรวจก่อนปล่อยอัปเดต

## โครงสร้าง
```
server.js            เซิร์ฟเวอร์ (เสิร์ฟเกม, ห้องออนไลน์, /health, /api/info, /api/whatsnew, /whatsnew)
info.json            ประกาศ + เวอร์ชัน (คุณแก้เอง)
changelog.json       ประวัติ What's New (เครื่องมือเขียนให้)
release/snapshot.json  ข้อมูลตัวละครตอนประกาศล่าสุด (เครื่องมือเขียนให้ ห้ามแก้เอง)
lib/                 ตัวโหลดตัวละคร + ตัวเทียบความต่าง
tools/               validate.js (ตรวจไฟล์), smoke.js (เล่นจริงในเบราว์เซอร์), whatsnew.js
.github/workflows/ci.yml   ด่านตรวจอัตโนมัติ
apk/build.yml        workflow สร้าง APK (ใช้ใน repo แยก ดู apk/README.txt)
public/              ตัวเกม
  data/config.js       ชื่อผู้สร้าง, เวลา Intro, เวอร์ชันของ build นี้
  data/units/*.js      ตัวละคร 1 ตัวต่อ 1 ไฟล์ (ดู TEMPLATE.txt)
  js/ css/ img/        โค้ด หน้าตา ภาพ
```

## ติดตั้งบน Render (ครั้งเดียว)
1. อัปโหลดทั้งโปรเจกต์ขึ้น GitHub repo
2. Render → New Web Service → เลือก repo → Runtime Node, Build `npm install`, Start `npm start`
3. Settings → **Auto-Deploy = After CI Checks Pass** (Render จะ deploy เฉพาะเมื่อด่านตรวจผ่าน ถ้าไม่ผ่านจะไม่แตะเวอร์ชันที่รันอยู่)
4. ถ้าอัปโหลดแล้วไม่ deploy เลย: ดูแท็บ Actions ว่าด่านตรวจขึ้นแดงหรือไม่ (ถ้าไม่มีด่านตรวจเลย Render ก็ไม่ deploy) แก้ไขชั่วคราวได้โดยตั้ง Auto-Deploy เป็น On Commit

## อัปเดตเกมโดยไม่ต้องแก้ทั้งเว็บ
อัปโหลดเฉพาะไฟล์ที่เปลี่ยน (ผ่านหน้าเว็บ GitHub ก็ได้) แล้วพิมพ์ข้อความ commit ให้สื่อความ เช่น "ปรับบาลานซ์ Juggerknight" ข้อความนี้จะกลายเป็นหมายเหตุใน What's New
- **ปรับตัวเลขตัวละคร/สกิล**: แก้ไฟล์ใน `public/data/units/` ไฟล์เดียว
- **เพิ่มตัวละครใหม่**: เพิ่มไฟล์ใหม่ใน `public/data/units/` (+ ภาพ `public/img/char/<id>.svg`) ไม่ต้องแก้ไฟล์อื่น เซิร์ฟเวอร์และเกมดึงไปเอง
- **ปล่อยเวอร์ชันใหม่ของแอป**: แก้ `version` ใน `public/data/config.js` และ `latest` ใน `info.json`
ถ้าไม่อยากให้ commit นั้นขึ้น What's New ให้ใส่ `[skip notes]` ในข้อความ commit

## ด่านตรวจ (ci.yml) ตรวจอะไร
1. `validate.js` ทุกไฟล์ JS โค้ดผิดรูปแบบไหม, ไฟล์ตัวละครครบฟิลด์ไหม/ไอดีซ้ำไหม, JSON ทุกไฟล์ถูกต้องไหม, รูปแบบเวอร์ชัน (มีคำเตือนถ้าขาดภาพ/ไอคอน/เอฟเฟกต์)
2. `smoke.js` เปิดเกมในเบราว์เซอร์จริงแล้วเล่นกับบอทหลายตา ต้องไม่มี error
3. ทดสอบห้องออนไลน์ 2 เบราว์เซอร์ (ขั้นตอนนี้เป็นคำเตือนเท่านั้น ไม่บล็อกการ deploy)
ข้อผิดพลาดข้อ 1–2 = ไม่ deploy ส่วนเซิร์ฟเวอร์เองก็ป้องกันอีกชั้น: ไฟล์ตัวละครที่เสียจะถูกข้ามและแจ้งใน log (`/api/status` ดูได้) แทนที่จะทำให้เซิร์ฟเวอร์ล้ม
ด่านตรวจจับได้เฉพาะของที่พัง ไม่ได้ตรวจว่าบาลานซ์ดีหรือไม่

## What's New ทำงานอย่างไร
- เซิร์ฟเวอร์เทียบข้อมูลตัวละครปัจจุบันกับ `release/snapshot.json` ความต่างคือ "อัปเดตล่าสุด" (ขึ้นที่หน้า `/whatsnew` และในกล่องจดหมายของเกมทันทีที่ deploy)
- หลังด่านตรวจผ่านบน branch หลัก workflow จะย้ายความต่างนั้นเข้า `changelog.json` และอัปเดต snapshot ให้เอง (commit ชื่อ "chore: publish What's New [skip ci]")
- ถ้าอัปโหลดซ้ำก่อนที่ขั้นนี้ทำงาน รายการจะรวมกันไม่หาย
- **ข้อจำกัด**: ตรวจจับได้เฉพาะข้อมูลในไฟล์ตัวละคร (HP, pop, ระดับ, ดาเมจ, คูลดาวน์, สตั๊น ฯลฯ, เพิ่ม/ลบตัวและสกิล) ตัวเลขที่ฝังอยู่ในโค้ด (เช่น ดาเมจสายฟ้าของ Nimbora ใน `js/mech/`) หรือการแก้หน้าตา/ระบบ จะไม่ขึ้นเอง ให้เขียนไว้ในข้อความ commit
- เรียกดูเองได้: `node tools/whatsnew.js --check`

## กล่องจดหมาย / เช็กเวอร์ชัน (`info.json`)
- `latest` เวอร์ชันล่าสุด, `minimum` เวอร์ชันต่ำสุดที่เล่นออนไลน์ได้ (แอปที่เก่ากว่านี้ถูกปฏิเสธ), `downloadUrl` ลิงก์ดาวน์โหลดแอป (แนะนำ GitHub Releases), `mail` รายการประกาศ `{id,date,title,body}` (ข้อความใหม่ต้องใช้ id ใหม่)
- What's New ล่าสุดถูกเติมเป็นข้อความบนสุดของกล่องจดหมายให้อัตโนมัติ

## ข้อจำกัดของเซิร์ฟเวอร์ฟรี
เซิร์ฟเวอร์ฟรีของ Render หลับเมื่อไม่มีคนใช้ ปลุกใช้เวลาราว 1 นาที (หน้า Intro ของเกมแสดงสถานะและมีปุ่ม "เล่นก่อน") ห้องออนไลน์เก็บในหน่วยความจำ จะหายเมื่อเซิร์ฟเวอร์รีสตาร์ท
